Design patterns are typical solutions to common problems in software design. Each pattern is like a blueprint that you can customize to solve a particular design problem in your code.

There are three main categories of design patterns:

- **Creational patterns**
- **Structural patterns**
- **Behavioral patterns**

An excellent explanation of each pattern can be found at the [Refactoring Guru](https://refactoring.guru/design-patterns).

## Most common ones

- Command (example: for tools and actions)
- Strategy (example: for planning and reasoning policies)
- Chain of responsibility (example: pipeline or multistep processing)
- Mediator (example: for multi-agent coordination)
- State pattern (example: for agent modes/phases)
- Adapter (example: unify different model providers)
- Decorator (example: logging, metrics, caching, safety layers)
- Facade (example: expose a simple AgentService.handle_request() API to the rest of your application)
- Factory / Abstract Factory (example: create agents or tools based on a config file like JSON)
